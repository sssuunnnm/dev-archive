이번 주(일요일 시작, 일~토 7일) 글감을 정하고 오늘 몫 초안까지 만드는 턴이야. 이 저장소(dev-archive)의 `CONVENTIONS.md`, `DESIGN_RULES.md`, `src/content.config.ts`를 기준으로 판단해. GitHub 이슈나 PR은 만들지 말고, 브랜치 생성/커밋/push까지만 하고 나머지는 나랑 대화하면서 정리해.

이 커맨드는 매주 일요일, **새로 연 세션**에서 실행하는 걸 전제로 한다 — 지난주 대화를 몰라도 되게, 필요한 맥락은 전부 아래 파일에서 읽어온다.

1. `git pull origin main`으로 최신 상태 확인.
2. 리포 루트의 `content-backlog.md`를 먼저 읽는다. 미체크(`- [ ]`) 항목이 있으면 이번 주 글감으로 우선 채택한다.
3. 백로그만으로 7개가 안 채워지면, `src/content/` 아래 기존 글들의 category/technology/tags/series를 훑어서 부족한 만큼 새로 글감을 정한다. type은 study/tutorial/tips/reference 위주로만 (troubleshooting/review는 실제 경험이 필요해서 제외). technology는 `content.config.ts`의 Technology Dictionary에 이미 등록된 값만 사용하고, 확신 없는 디테일에 의존하는 주제는 피한다.
4. 리포 루트에 `content-plan.md` 파일을 새로 쓴다(기존 파일 있으면 덮어씀). 제목에 이번 주 기간(오늘 날짜~6일 뒤 날짜)을 적고, 7개 글감을 `- [ ] 제목 | slug | category | technology | tags | type | 한줄 개요` 형식으로 체크리스트로 적는다.
5. `content-plan.md`를 커밋(`chore: 주간 글감 계획 갱신`)하고 `git push origin main`으로 바로 push한다 (브랜치 없이 main 직접 — CONVENTIONS.md 5-5 예외).
6. 2번에서 백로그로 채택한 항목이 있으면 `content-backlog.md`에서 지우고 같이 커밋(`chore: 글감 백로그 반영`) 후 push한다.
7. 오늘(일요일) 몫인 첫 번째 글감으로 브랜치(`feat/<slug>`) 생성 → CONVENTIONS.md/DESIGN_RULES.md 규칙에 맞춰 frontmatter(`draft: true`) 포함 전체 본문 작성 → CONVENTIONS.md 7절 "발행 전 최종 확인" 체크리스트로 스스로 검토 → 인터랙티브 데모는 개념이 시각적으로 확인될 때만 넣고 넣었다면 `astro dev --background`로 라이트/다크 모드 렌더링 확인 → 커밋(`feat: <제목> 글 추가`) 후 `git push -u origin <브랜치명>`. PR은 만들지 않는다.
8. **이번 주 일일 자동화가 이 세션(지금 이 대화)으로 들어오도록 트리거를 재설정한다**:
   a. `mcp__Claude_Code_Remote__get_session`을 인자 없이 호출해서 이 세션의 정보를 확인한다 (지금 세션이 새 대상이 된다).
   b. `mcp__Claude_Code_Remote__list_triggers`로 이름이 "dev-archive 일일 글 초안 (월~토)"인 트리거를 찾는다.
   c. 있으면 `mcp__Claude_Code_Remote__delete_trigger`로 그 트리거를 지운다 (지난주 세션에 물려있던 것이므로).
   d. `mcp__Claude_Code_Remote__create_trigger`로 같은 이름·cron(`0 0 * * 1-6`)의 트리거를 새로 만든다. `persistent_session_id`와 `create_new_session_on_fire`는 둘 다 생략해서 기본값(=지금 이 세션)을 대상으로 하게 한다. `initiation`은 `human_request`로 하고, `prompt`는 아래 내용을 그대로 쓴다:

   ```
   오늘 발행할 글 1개의 초안을 작성하는 자동화 턴이야. GitHub 이슈나 PR은 만들지 말고, 브랜치 생성/커밋/push까지만 하고 나머지는 나랑 대화하면서 진행해.

   1. `git pull origin main`으로 최신 상태 확인.
   2. 리포 루트의 `content-plan.md`를 읽어. 파일이 없으면 "이번 주 계획 파일이 없다"고 알리고 종료해.
   3. 체크되지 않은(`- [ ]`) 항목 중 가장 위의 것을 오늘 글감으로 선택해. 모두 체크되어 있으면 "오늘 몫 없음"이라고 알리고 종료해 (중복 방지).
   4. CONVENTIONS.md/DESIGN_RULES.md 규칙에 맞춰 브랜치(`feat/<slug>`) 생성 → frontmatter(`draft: true`) 포함 전체 본문 작성 → CONVENTIONS.md 7절 "발행 전 최종 확인" 체크리스트로 스스로 검토 → 인터랙티브 데모를 넣었다면 `astro dev --background`로 라이트/다크 모드 렌더링 확인.
   5. `content-plan.md`에서 해당 항목을 `- [x]`로 바꾸고 커밋(`chore: 글감 체크 - <제목>`) 후 `git push origin main`으로 바로 push해.
   6. 글 브랜치도 커밋(`feat: <제목> 글 추가`) 후 `git push -u origin <브랜치명>`. PR은 만들지 마.
   7. 오늘 작성한 글 요약과 브랜치명, 로컬 확인용 명령어(`git fetch origin <브랜치명>`, `git checkout <브랜치명>`, 필요시 `npm install`, `astro dev --background`)를 안내해줘. 그 다음은 여기서 나랑 대화하면서 진행해.

   글감 항목의 technology가 Technology Dictionary에 없거나 정확하게 쓸 자신이 없으면 무리하지 말고 상황을 설명하고 종료해.
   ```

9. 마지막으로 이번 주 글감 7개 목록(백로그에서 가져온 항목 표시), 오늘 작성한 글의 브랜치명·요약, 로컬 확인 명령어(`git fetch origin <브랜치명>`, `git checkout <브랜치명>`, 필요시 `npm install`, `astro dev --background`)를 안내한다. 그 다음 단계(리뷰, PR 생성 여부, 발행)는 여기서 대화로 정한다.

적절한 글감을 도저히 못 찾겠으면 무리해서 채우지 말고, 가능한 만큼만 `content-plan.md`에 적고 상황을 설명한다.
