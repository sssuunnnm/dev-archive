## 한 줄 요약

그리디는 "매 순간 당장 최선인 선택을 해도, 결국 전체 최적해가 되는" 문제에서만 통한다 — 이게 성립하는지 확인하는 게 그리디 문제 풀이의 8할이다.

## 왜 (배경/문제 상황)

그리디는 코드 자체는 짧고 간단한데, "이 문제에 그리디를 써도 되는지"를 판단하는 게 어렵다. 그리디로 짰는데 반례가 있어서 틀리는 경우가 흔하다. 그래서 그리디를 쓰기 전에 "이 선택 기준이 항상 맞는지" 확인하는 습관이 중요하다.

## 본문

### 그리디가 통하는지 확인하는 법

그리디가 성립하려면 아래 두 조건이 필요하다.

1. **탐욕적 선택 속성**: 지금 당장 최선인 선택이 전체 최적해의 일부가 된다.
2. **최적 부분 구조**: 부분 문제의 최적해를 모으면 전체 최적해가 된다.

이걸 이론적으로 증명하기는 어렵지만, 실전에서는 "반례를 손으로 만들어보는" 게 훨씬 빠르다. 그리디 기준을 하나 세웠으면, 그 기준이 깨지는 극단적인 예시를 2~3개 직접 만들어보고 답이 맞는지 확인한다.

### 문제 신호 → 그리디 기준 매칭

| 문제에서 이런 게 보이면 | 그리디 기준 |
|---|---|
| "최소 개수로 나눠라" (동전, 거스름돈 등) | 큰 단위부터 채운다 |
| "겹치는 구간을 최대한 안 겹치게 골라라" | 끝나는 시간이 빠른 것부터 고른다 |
| "정해진 자원으로 최대한 많이/적게" | 비율(가치/비용)이 좋은 것부터 고른다 |
| "순서를 정해서 총 대기시간/비용을 최소화" | 짧은/작은 것부터 처리한다 |

### 패턴 1. 큰 단위부터 채우기 (동전 문제류)

```cpp
int coinChange(vector<int>& coins, int amount) {
    sort(coins.rbegin(), coins.rend()); // 큰 단위부터
    int count = 0;
    for (int c : coins) {
        count += amount / c;
        amount %= c;
    }
    return amount == 0 ? count : -1;
}
```

**주의**: 이 패턴은 동전 단위가 서로 배수 관계일 때만 항상 맞다 (예: 1, 5, 10, 50, 100원). 단위가 임의의 값이면(예: 1, 3, 4원으로 6원 만들기) 큰 단위부터 채우는 그리디가 틀릴 수 있다 — 이럴 땐 그리디가 아니라 DP로 풀어야 한다.

### 패턴 2. 구간 스케줄링 (끝나는 시간 기준 정렬)

예: "회의실 배정" 유형. 시작 시간이 아니라 **끝나는 시간**을 기준으로 정렬하는 게 핵심이다.

```cpp
sort(meetings.begin(), meetings.end(), [](auto& a, auto& b) {
    return a.second < b.second; // 끝나는 시간 기준 오름차순
});

int count = 0;
int lastEnd = -1;
for (auto& [start, end] : meetings) {
    if (start >= lastEnd) {
        count++;
        lastEnd = end;
    }
}
```

시작 시간 기준으로 정렬하면 틀리는 경우가 많다. "빨리 끝나는 걸 먼저 골라야 남는 시간이 많아진다"는 게 이 그리디의 핵심 논리다.

### 패턴 3. 비율(가치/비용) 기준 정렬

예: "배낭에 쪼개서 담을 수 있는 물건들 중 최댓값" 유형(분할 가능한 배낭 문제).

```cpp
sort(items.begin(), items.end(), [](auto& a, auto& b) {
    return (double)a.value / a.weight > (double)b.value / b.weight;
});
```

단, 물건을 쪼갤 수 없는 일반 배낭 문제(0/1 Knapsack)는 이 그리디가 안 통하고 DP로 풀어야 한다 — "쪼갤 수 있는지"가 그리디 적용 가능 여부를 가르는 조건이다.

## 예제

"체육복" 유형(프로그래머스): 여벌 체육복이 있는 학생이 자신보다 앞 번호, 뒷번호 학생에게 빌려줄 수 있을 때, "본인 체육복을 먼저 챙긴 학생은 건드리지 않고, 여벌 있는 학생부터 순서대로 좌우를 확인"하는 방식이 그리디에 해당한다. 이런 유형은 "먼저 확정할 수 있는 것부터 확정하고 넘어간다"는 그리디의 전형이다.

## 주의사항

- 그리디로 풀었을 때 예제 테스트는 통과하는데 실제 채점에서 틀리는 경우가 잦다. 그리디 기준을 정했으면 꼭 반례를 직접 만들어 검산한다.
- "그리디처럼 보이지만 사실 DP인 문제"가 많다 (동전 단위가 배수 관계 아닐 때, 물건을 못 쪼갤 때 등). 그리디가 안 통하는 대표 조건 두 가지(단위가 배수 관계 아님 / 쪼갤 수 없음)를 외워두면 오판을 줄일 수 있다.
- 정렬 기준을 잘못 잡는 게 그리디 문제의 가장 흔한 실수다 (시작시간 vs 끝시간, 오름차순 vs 내림차순). 기준을 정했으면 손으로 작은 예제 하나를 끝까지 따라가본다.
