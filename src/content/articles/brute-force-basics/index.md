## 한 줄 요약

완전탐색은 "모든 경우를 어떻게 만들어낼 것인가"만 정하면 되는데, 그 방법이 for문 중첩/순열/조합/백트래킹 중 뭔지 헷갈리는 게 진짜 문제다.

## 왜 (배경/문제 상황)

완전탐색은 프로그래머스에서 출제빈도가 제일 높은 유형인데, 막상 "이거 완전탐색으로 풀어라"라고 대놓고 나오지 않는다. 대신 "가능한 모든 경우를 확인해라", "몇 가지 방법이 있나" 같은 말로 위장돼 있어서, 신호를 못 잡으면 괜히 어려운 알고리즘을 찾다가 시간을 버린다.

## 본문

### 완전탐색이 통하는지 먼저 확인하기

완전탐색을 쓰기 전에 제약조건(문제에 주어진 n의 범위)부터 본다. 시간제한이 보통 1초고, 연산은 대략 1억(10^8)번까지 여유롭다고 보면:

| n의 범위 | 가능한 방식 |
|---|---|
| n ≤ 10 | 순열(10! ≈ 360만) 완전탐색 가능 |
| n ≤ 20 | 비트마스킹(2^20 ≈ 100만) 완전탐색 가능 |
| n ≤ 1,000,000 | O(n) 또는 O(n log n)만 가능, 완전탐색 불가 |

이 표를 먼저 확인하면 "완전탐색으로 풀 수 있는 문제인지"부터 감이 잡힌다. n이 크면 완전탐색이 아니라 다른 접근(그리디, DP, 이분탐색 등)을 찾아야 한다는 신호다.

### 문제 신호 → 방법 매칭

| 문제에서 이런 게 보이면 | 방법 |
|---|---|
| "순서를 바꿔서 만들 수 있는 모든 경우" | 순열 (`next_permutation`) |
| "순서 상관없이 몇 개를 뽑는 모든 경우" | 조합 |
| "선택하거나 안 하거나"를 반복 | 비트마스킹 또는 재귀(백트래킹) |
| "조건을 만족하는 순간 더 진행 안 해도 됨" | 백트래킹 (가지치기) |
| 그냥 이중 for문으로 다 확인 가능 | 단순 중첩 for문 |

### 패턴 1. 순열 (순서가 의미 있을 때)

```cpp
vector<int> v = {1, 2, 3};
sort(v.begin(), v.end()); // next_permutation은 정렬된 상태부터 시작해야 전체를 다 돈다

do {
    // v가 하나의 순열 상태, 여기서 조건 확인
} while (next_permutation(v.begin(), v.end()));
```

`next_permutation`은 반드시 정렬된 상태에서 시작해야 모든 순열을 빠짐없이 돈다는 걸 기억한다.

### 패턴 2. 조합 (순서 상관없을 때)

재귀로 "몇 번째 인덱스부터 몇 개를 더 뽑을지"를 넘기면서 만든다.

```cpp
vector<int> picked;
void combination(vector<int>& v, int start, int r) {
    if (r == 0) {
        // picked가 하나의 조합, 여기서 조건 확인
        return;
    }
    for (int i = start; i < v.size(); i++) {
        picked.push_back(v[i]);
        combination(v, i + 1, r - 1); // i+1로 넘겨서 같은 원소 재사용 안 함
        picked.pop_back();
    }
}
```

`start`를 `i+1`로 넘기는 부분이 순열과 조합을 가르는 핵심이다. 순열은 이미 뽑은 것만 빼고 전부 다시 후보가 되지만, 조합은 뒤쪽 인덱스만 후보가 된다.

### 패턴 3. 백트래킹 (선택/비선택 반복 + 가지치기)

"뽑거나 안 뽑거나"를 매 원소마다 결정하면서, 조건이 이미 깨졌으면 더 안 들어가고 되돌아온다.

```cpp
void backtrack(vector<int>& v, int idx, int sum, int target) {
    if (sum > target) return; // 가지치기: 이미 틀렸으면 더 안 감

    if (idx == v.size()) {
        if (sum == target) {
            // 조건 만족
        }
        return;
    }

    backtrack(v, idx + 1, sum + v[idx], target); // 이 원소를 선택
    backtrack(v, idx + 1, sum, target);           // 이 원소를 선택 안 함
}
```

가지치기(`if (sum > target) return;`)가 없으면 이건 그냥 2^n 완전탐색이다. 가지치기가 있어야 백트래킹이라 부를 수 있고, 실제 성능 차이도 여기서 난다.

## 예제

"모의고사" 유형(프로그래머스): 세 사람이 각자 정해진 패턴을 반복하며 답을 찍는다. 패턴 배열을 답 개수만큼 나머지 연산으로 순환시키면서 비교하는 문제로, 순열/조합이 아니라 "패턴을 인덱스 나머지로 순환시키는" 단순 완전탐색이다.

```cpp
vector<int> pattern1 = {1, 2, 3, 4, 5};
for (int i = 0; i < answers.size(); i++) {
    if (answers[i] == pattern1[i % pattern1.size()]) {
        score1++;
    }
}
```

이런 유형은 순열/조합 templates가 아니라 "인덱스를 어떻게 순환시킬지"만 확인하면 되는, 완전탐색 중에서도 제일 단순한 형태다.

## 주의사항

- `next_permutation`은 중복 원소가 있으면 같은 순열을 건너뛴다 (이게 오히려 필요한 경우도 있고, 아닌 경우도 있으니 문제 조건을 확인한다).
- 조합에서 `start`를 `i`로 넘기면 같은 원소를 여러 번 뽑는 "중복조합"이 되고, `i+1`로 넘기면 일반 조합이 된다 — 문제가 중복 허용인지부터 확인한다.
- 가지치기 조건을 재귀 맨 앞에 안 두고 맨 뒤에 두면, 가지치기 효과 없이 끝까지 다 돌고 나서야 걸러진다. 조건은 항상 재귀 진입 직후에 체크한다.
- n의 범위를 확인 안 하고 무작정 완전탐색부터 짜면, 코드는 맞는데 시간초과가 나는 경우가 많다. 항상 제약조건표부터 본다.
